# Keep Hermes surfaces outside Organization scope

**Status: accepted.**

Project Forge currently places Personal Chat and the Shared Local Agent catalog under Organization URLs even though the Hermes runtime is application-level, Shared Agents are global to the local installation, and Personal Chat is User-scoped rather than Organization-scoped. The authenticated Hermes Surface is therefore separate from the Organization Surface: `/~` is the Organization Picker, `/hermes` is a convenience entry that redirects to `/hermes/chat`, `/hermes/chat` is Personal Chat, and `/hermes/agents` is the Shared Local Agent surface; Organization routes retain Organization-owned work and administration, while the old Organization Chat and Agents routes are not preserved because the application has not reached production.

The two surfaces reuse the existing authenticated shell implementation through distinct navigation modes, but Hermes pages do not create or require an Organization Scope. Hermes APIs remain global and server-authorized, and this route decision does not move authorization into the browser or duplicate Hermes transcript authority.

Hermes Chat uses a persistent nested chat layout for `/hermes/chat` and `/hermes/chat/:sessionId`. The new-chat route is a client-only draft state: focusing or selecting an Agent does not persist a Session. The first prompt creates the User-scoped Session, optimistically keeps the prompt visible, and uses client-side `router.replace` with `scroll: false` to move to the Session URL without a document refresh. If creation fails, the draft remains available and the same operation is exposed as Retry; if sending fails after creation, Retry reuses the same `clientMessageId` and Session rather than creating a duplicate.

All Session summaries returned for the authenticated user are rendered in one Hermes sidebar section across Agents. A Session link targets `/hermes/chat/:sessionId`, and the AppHeader resolves its title as Agent-generated title, then safe preview/first-message fallback, then `Chat`. The workspace remains mounted in the nested layout so the WebSocket, optimistic message, hydration, reconnect, and scroll state survive the URL transition.

The browser boundary remains unchanged: **Browser ห้ามได้รับ secret หรือ filesystem credential**. **Browser ส่งได้เฉพาะข้อความ, profile/agent, session, answers และ validated actions**. **ไม่ push, PR, deploy หรือ migration อัตโนมัติ เว้นแต่ผู้ใช้ร้องขอโดยตรง**.
