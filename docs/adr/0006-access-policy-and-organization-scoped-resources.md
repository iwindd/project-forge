# Central access policy and organization-scoped resources

**Status: accepted.** The Access module evaluates authorization policies while Organization owns roles, permissions, and membership facts and Project owns project data. Only active members can access projects belonging to an active organization; Archived and Suspended organizations deny normal access. Project sharing and project-level roles are out of scope. The `manageOrganization` permission governs membership, invitations, and organization-role administration; `manageProject` governs project mutations, while read/list access follows active organization membership. Organization-owned resources use the `/organizations/:organizationId/...` API namespace; user-scoped resources such as authentication and profile remain outside that namespace. This keeps policy decisions out of controllers and prevents resource ownership from being inferred from a global user or session context.
